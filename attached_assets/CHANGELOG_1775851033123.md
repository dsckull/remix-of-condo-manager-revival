## Contexto do Projeto

Sistema de gestão condominial com bot IA via Telegram. Produto comercial
em desenvolvimento com modelo de assinatura (Free / Pro R$99 / Enterprise R$299).

**Histórico de versões anteriores (não estão neste repositório):**
- `Condo-Manager` (Replit) — monorepo pnpm, Express + Drizzle + PostgreSQL,
  sem autenticação, 10 tabelas, deploy via Railway. Versão funcional mas sem
  auth e sem deploy estável.
- `Brand-Visual-Identity` (Replit/Lovable) — mesmo backend, design neomórfico
  implementado, sem autenticação, mockup-sandbox travando o build.
- `hubble-home-care` (este repositório, Lovable) — reescrita completa,
  arquitetura simplificada sem Express, Supabase direto, autenticação real.
  **Esta é a versão ativa.**

## Arquitetura de Decisões

### Por que Supabase direto em vez de Express?
O Express + Drizzle do Condo-Manager original exigia Railway ($5/mês) e
complexidade de deploy. Com Supabase JS direto, o frontend faz as queries
sem servidor intermediário. Trade-off: menos controle sobre lógica de negócio
complexa, mas zero infraestrutura adicional.

### Por que Lovable em vez de Replit?
Cotas do Replit esgotadas. Lovable renova créditos por ciclo e tem
integração direta com GitHub, permitindo editar em qualquer plataforma
(Cursor, VS Code, Replit com nova conta) e sincronizar via git.

### Por que React Router em vez de Wouter?
Padrão do Lovable. Funciona igual para este caso de uso.

## Como continuar em outra plataforma

1. Clone: `git clone https://github.com/dsckull/hubble-home-care`
2. Instale: `npm install` (ou `bun install`)
3. Crie `.env` local com as variáveis do Supabase (peça ao Diego)
4. Rode: `npm run dev`
5. Leia este arquivo + `.lovable/plan.md` antes de qualquer alteração
6. Ao terminar: commit com mensagem descritiva + atualize este CHANGELOG
